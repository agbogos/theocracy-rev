## `b148608` — Linker: share R_386_COPY storage (drop manual singleton/flag syncs)

*2026-07-22 · Adam Bogos · `b148608de71b8fb987f18a019c07d2ee1bd7e714`*

R_386_COPY moves storage ownership of libmvos-defined globals to the game .bss;
real ld.so then resolves every reference in both images to that copy. guestlink
only rebound the GOT, but libmvos reaches the singletons (VVC/Intuition/...),
EnvSystem, and the cApplication.* flags via R_386_32 to its own DSO-local slot —
so libmvos wrote its slot while the game read its copy. The workaround was three
one-shot mvos<->game syncs in main.cpp plus a flags mirror.

Fix: for a non-vtable COPY'd global, resolve libmvos's own absolute refs to the
game copy too (guestlink copy_to_game / build_idx), so storage is genuinely
shared — exactly ld.so's behavior. Vtables (__vt_*) still point at libmvos's own
relocated body (dispatch must hit libmvos code; the game copy is a byte-identical
snapshot). Removed all three manual syncs + the flags mirror (~50 lines).

Verified: 45 globals shared; VVC/VKeyboard/VMouse/SoundCard/VCD/SystemMemory/
IPCSystem/LocaleDataBase + EnvSystem + flags all populate themselves; boot ->
Single Player -> Realm Shell clean; movies+audio unaffected; 0 unimplemented.

Doc: guest-libmvos.md G12; task_fifo item retired.

## `78f6e86` — Add THEOC_LOUD_ABORT: guest-backtrace-on-abort debug mode

*2026-07-22 · Adam Bogos · `78f6e86f2057b3b6cbe77abb2514f80982d78156`*

Guest Fatal() ends in abort() (HLE'd libc). Default bring-up policy keeps abort
non-fatal (log + return) so the caller continues past non-critical Fatals — the
happy path is abort-free, so this never fires in normal play. The risk was a
real fault hiding as a silent continue/restart.

THEOC_LOUD_ABORT=1 turns abort into a diagnostic: walk the g++ 2.95 EBP frame
chain and print a labeled backtrace (game 0x... / mvos+0x..., each mapping to the
matching Ghidra DB), then request_stop() the current call so the failure surfaces
at its origin. exit/_exit unchanged.

Verified: default mode reaches Realm Shell clean with 0 aborts; loud mode against
forced Fatals (empty data root) prints the backtrace pinpointing the aborting
ctor and stops. Doc: guest-libmvos.md G13; task_fifo item retired.

## `1f9c4fd` — Timing: decouple heartbeat, frame rate and audio from the render loop

*2026-07-24 · Adam Bogos · `1f9c4fdbf467fccf87c0b5515ae88110f81a99cb`*

Province was pinned at ~12fps with the emulator ~95% idle — not a slow
renderer but a stalled game clock. Three coupled fixes:

- Heartbeat in usleep. The 30Hz SIGALRM (_TimerFunction) was serviced
  only at present, so it ran at ~6Hz and the game's frame limiter
  (cSyncSystem::Sleep) over-slept ~68ms/frame waiting for it — a circular
  stall. Deliver a due tick from inside the usleep trap, exactly as
  EINTR-from-SIGALRM does on Linux, and never sleep past the next tick.
  → 12fps → 40fps, clock back to 30Hz. THEOC_LEGACY_SLEEP reverts.

- Frame-rate cap. The engine steps physics once per rendered frame, so
  the faster render made the sim run ~1.5x fast. Clamp the minimum
  present interval to the design cadence (default 33ms = 30Hz, the game's
  own timer rate; THEOC_FRAME_MS), measured present-to-present so the
  game's own pacing isn't double-limited. → correct sim speed.

- Audio decoupled from fps. The mixer was green-run only at present and
  gated to ~11 fragments/s == the drain rate (zero margin → underrun
  stutter, worse at low fps). Make it buffer-driven (top the queue to a
  small target, THEOC_AUDIO_MS ~120ms = the audio latency) and service it
  from usleep as well as present. → full queue, 0 steady-state underruns.

## `4395257` — Guest heap: reserve host objects, and make free() actually free

*2026-07-24 · Adam Bogos · `43952573ec5b2bcf7928930645794dbca9a60676`*

Two heap-lifetime bugs, both consequences of the same naive bump
allocator. Found by the manual QA pass (user-test.md), which is now
complete and closed out.

G14 — cold-boot Load Game crashed in cIntuition::ActivateScreen
(mvos+0x8d84a) reading [Intuition+0x24], the active cScreen*, which
held 0xc4c4c5c4: non-null, so the null guard passed, then the deref
faulted. That value is two adjacent RGB565 pixels — the singleton had
been painted over with bitmap data. main.cpp planted the cIntuition
object at a hardcoded HEAP_BASE+0xf00000 ("carve from high heap"), an
address inside the bump arena that was never reserved, so once
cumulative allocation passed 15 MB the guest got it back as ordinary
heap. Measured: 3.3 MB at the menu but a burst to 41 MB on game entry,
so the object survived the menu and died the moment a game started —
matching the repro exactly. Now reserved via TrapLayer::guest_alloc.

G15 — Chronicle -> quit -> new campaign then died with [heap] OUT OF
MEMORY and a write through a NULL malloc result (game 0x82c9914,
mov [eax+edx*4],ecx with eax=0). free() was literally a no-op, so every
scenario load leaked its whole working set and two loads exhausted the
128 MB arena. The engine does free correctly — libmvos's heap layers
(cHeap_Compatibility::Free, FreeHeapBlock, cSystemMemory::Free) all
bottom out in the imported free we were discarding. Replaced with a real
allocator: bump frontier plus a coalescing free list, indexed by address
for merging and by size for best-fit O(log n) allocation; realloc frees
the old block, __builtin_vec_delete frees. Province went from a 50.1 MB
leaked frontier to 28.6 MB live / 28.7 MB frontier.

Both crash routes retested clean by the user.

Reporting now splits live (held now) from frontier (high-water of fresh
memory) in the trap report and the THEOC_FPS line — with a no-op free
those were the same number, which is why a 50 MB-per-load leak was
invisible. THEOC_HEAP_TEST=1 soaks the allocator standalone: it guards

## `e6288d9` — Sockets: real BSD transport with the Linux->BSD translations

*2026-07-26 · Adam Bogos · `e6288d91c8921351636933a81aa41254b45b1bbd`*

Sockets were unconditional lies (socket->32, bind->0, recv->0) -- enough
for the single-instance lock and nothing else. Now real, sharing the
existing fd table (the guest tells us socket vs file by calling
send/recv rather than read/write, so close already worked).

The work is almost entirely translation, because the guest is a 1999
Linux i386 binary and we are BSD. Four divergences, each of which
produces a plausible wrong answer rather than an error:

  1. sockaddr_in: Linux u16 family @0; BSD u8 sin_len @0, u8 family @1.
  2. O_NONBLOCK: Linux 0x800, BSD 0x0004. Forwarding it sets O_ASYNC plus

     single-threaded emulator on the first recv.

     the guest would read "no data yet" as a hard error.

     port=5043, INADDR_ANY}. Linux tolerates AF_UNSPEC on a socket
     already created AF_INET; BSD returns EAFNOSUPPORT.

Number 4 was not predicted. It was found by dumping the raw guest
sockaddr after a translation failure -- the first cut returned -1
silently, which surfaced as an unexplained Fatal three layers up in
guest code and cost a debugging cycle. The failure path now always dumps
the raw bytes, because a silently rejected sockaddr is unfalsifiable
from the log.

select is real over the guest's 1024-bit fd_set, but its timeout is
capped at 20ms: single-threaded, so honouring a long guest timeout would
freeze render, input and the audio slice. Capping returns "nothing
ready" early and the guest polls again, which its non-blocking design
already expects. gethostbyname had to be real too -- cIPCO_TCPIP's ctor

## `14481df` — Fix __xstat writing 96 bytes into an 88-byte struct stat

*2026-07-26 · Adam Bogos · `14481df02d370a1246838166a57155facf509129`*

Root cause of the netgame map-selection crash. Linux/i386 struct stat

__xstat ran 8 bytes past the caller's local and zeroed the saved EBP and
return address sitting immediately after it.

a fault at eip=0 with no frame pointer, several frames from the actual
damage. Only the netgame map dialog constructs a cDirent, which is why
single-player never tripped it.

mode @0x10, nlink @0x14, uid/gid, rdev(8) @0x20, size @0x2c, blksize,
blocks, and a/m/ctime at 0x38/0x40/0x48. Two details beyond the size:
S_IFMT bits agree between Linux and BSD so the mode passes through, and
passing the REAL mode matters -- the old code hardcoded S_IFREG, which
would have reported every directory as a regular file and broken the
enumeration even once the overflow was gone. st_size also moves from a
guessed +0x14 to its real +0x2c.

Found by instrument, after three inferences that were each stated more
confidently than the evidence supported: a stack slot read as a return
address, a GOT value read from the file on disk rather than guest memory,
and a truncated grep taken as proof of a missing export. The zero-GOT
scan reported 0 slots and killed the GOT theory; the THEOC_TRACE block
ring then showed mvos+0x4c1e8 was a function EPILOGUE rather than a call
site, which reframed the whole thing -- the function returned to 0 --
and the two trap slots in the trace decoded to strrchr and __xstat.

Generalisable: eip=0 with EBP=0 is a smashed frame, not a null call.
Look for who wrote past a buffer, not for an unresolved symbol.

Regression: game reaches Realm Shell, 0 faults, 0 unimplemented, 0 zero
GOT slots; server still binds 5042.

## `e0dde5d` — Translate errno in the read/write traps, not just the socket ones

*2026-07-26 · Adam Bogos · `e0dde5d9649844019f92c231d5465ac8dcd6018a`*

cIPCO_TCPIP polls its socket with plain read()/write(), not recv()/send(),
so both landed in the generic file traps and passed the host errno straight
through. libmvos switches on errno 4..22 and drops anything outside that
window into its generic "unknown error" state (5). Linux EAGAIN is 11 and
maps to state 3, which the dedicated server accepts silently; BSD EAGAIN is
35, which fell off the end of the switch.

Every accepted connection is non-blocking -- cIPCServer_TCPIP::Listen does
fcntl(fd, F_SETFL, 0x800) on it -- so "no packet yet" is the steady state,
not an edge case. That turned each idle poll of each connected player into
`Error(n): 5`, thousands a minute, while the game itself played fine: the
misreported path was the idle one.

to_linux_errno() already existed with the right mapping; it was only wired
into socket(), bind(), connect(), accept(), send() and recv(). Route
read/write/open/remove through it too, and fill EBADF on the bad-fd paths
instead of returning -1 over a stale errno.
